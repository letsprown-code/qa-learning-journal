## O que é o Crowdtest

O **Crowdtest** é a plataforma de testes colaborativos (crowdtesting) da **Base2**, uma empresa de testes de software de Belo Horizonte. Tudo é em **português**. Existem dois modelos de trabalho:

| Modelo | Como funciona |
| --- | --- |
| **Pay-Per-Test** (casos de teste) | Sigo um roteiro pronto, passo a passo. Recebo pela execução aprovada. |
| **Pay-Per-Bug** (teste exploratório) | Exploro as funcionalidades liberadas atrás de falhas. Recebo por bug aprovado. |

## 1. Cadastro

- Dá para se cadastrar pelo site ou pelos apps de Android e iOS.
- Preencher o **máximo de informações** possível: muitos projetos procuram um perfil ou um aparelho específico.
- Se o meu aparelho não estiver na lista, peço a inclusão por e-mail ao suporte (contato@crowdtest.com.br).

## 2. Gravação de tela

**Todo teste precisa ser gravado.** O vídeo é a evidência que a equipe usa para aprovar.

| Onde testo | Como gravo |
| --- | --- |
| Android | Ligar as **Opções do desenvolvedor** e **Mostrar toques**, para os toques aparecerem no vídeo. App sugerido: **AZ Recorder** |
| iPhone e iPad | Gravação de tela do próprio sistema |
| Mac | **QuickTime Player**: Arquivo, Nova gravação de tela |
| Windows | **Screenpresso** |

## 3. Como fico sabendo dos projetos

| Tipo de projeto | Como entro |
| --- | --- |
| **Público** | Sem formulário: entro no site e abro **"Projetos Disponíveis"**. As vagas são limitadas. |
| **Privado** | Pede um perfil específico (cidade, idade, banco, aparelho). Tem formulário de inscrição e o convite chega por **e-mail** (olhar também o spam). |

- A **maioria dos projetos é privada**. Por isso o perfil completo faz tanta diferença.
- Os projetos são divulgados nas redes sociais, como o Instagram @crowdtestbrasil.

## 4. Como executar um caso de teste

1. Abrir o projeto e clicar em **"Executar próximo teste"**. O valor aparece no título.
2. Ler com atenção: título, descrição, **pré-condições**, funcionalidade, **resultado esperado** e observações. Se eu não puder fazer, dá para **pular ou cancelar**.
3. Gravar a tela, seguir os passos e marcar cada passo concluído.
4. Preencher os campos:

| Campo | Obrigatório? |
| --- | --- |
| Passos extras | Não |
| **Resultado encontrado** | Sim |
| Observações adicionais | Não |
| **Dispositivo** | Sim |
| **Evidências** (vídeo e, se houver, prints) | Sim |

5. Escolher a situação do teste:

| Situação | Quando usar |
| --- | --- |
| **Passou** | O objetivo foi alcançado, **mesmo com pequenas falhas** que não impedem o objetivo |
| **Falhou** | O objetivo principal **não** foi alcançado |
| **Bloqueado** | Não consegui testar porque **a aplicação falhou** antes |

6. Salvar, esperar e fechar.

**Prazo:** cada teste tem um tempo limite, normalmente de **2 horas**, mostrado no topo da tela. Se o tempo acabar, o teste vai para outra pessoa.

## 5. Como registrar um bug no teste exploratório

- **Antes de começar:** ler a lista de **funcionalidades permitidas**. Bug fora dela é reprovado.
- **Gravar a tela do início ao fim, com no mínimo 45 minutos** (regra do e-book de dez/2025).
- Média de pagamento: **R$ 60 por projeto** exploratório, e cada bug é pago separado.
- Gravar a tela, explorar e, ao achar um problema, clicar em **"Nova Ocorrência"**.

| Campo | Obrigatório? |
| --- | --- |
| **Título** (específico, nunca genérico) | Sim |
| **Tipo** do bug | Sim |
| **Descrição** | Sim |
| **Passos** (o caminho até o bug) | Sim |
| **Resultado esperado** | Sim |
| **Funcionalidade** afetada | Sim |
| **Dispositivo** e **Evidências** | Sim |
| Pré-condição e informações adicionais | Não |

- Só a **primeira pessoa** que registra um bug recebe por ele. Antes de registrar, pesquiso se ele já existe.
- Quando o **orçamento** de bugs do projeto acaba, o projeto é **pausado sozinho**. Ele pode voltar se houver reprovações ou se o cliente aumentar o orçamento.

## 6. Esclarecimentos e reprovações

- Se a equipe pedir correção ou mais informação, tenho **24 horas** para responder pelo botão **"Esclarecimentos"**. Sem resposta, o item é **reprovado automaticamente**.

## 7. Tipos de bug e valores

| Tipo | O que é | Valor (pode mudar sem aviso) |
| --- | --- | --- |
| **Impeditivo** | Trava o app ou impede uma ação, como o app fechar sozinho | R$ 20 |
| **Segurança** | Deixa ver uma informação que não deveria aparecer | R$ 20 |
| **Funcional** | Algo não funciona como deveria | R$ 10 |
| **Interface** | Problema visual, como um botão fora do lugar | R$ 5 |
| **Melhoria** | Sugestão para deixar o app melhor | R$ 3 |
| **Texto** | Erro de digitação ou de ortografia, palavra repetida | R$ 2 |

Caso de teste: em média **R$ 20**, conforme a dificuldade.

## 8. Pagamento

- **Todo dia 10**, **só por PayPal** e só do que foi **aprovado**.
- O e-mail do PayPal vai em **Perfil, Dados financeiros, Editar**.

## 9. Projeto de Boas-Vindas

- É um treino **sem pagamento** que mostra se estou pronta para os projetos públicos.
- Preciso ter **um teste executado e um bug aprovados** nele para liberar os projetos públicos.

## Pontos de atenção para a prova

- "Passou" vale mesmo com uma falha pequena que não impede o objetivo.
- "Bloqueado" é quando a falha da aplicação impede o teste. Se eu não posso fazer, eu **pulo ou cancelo**.
- **2 horas** é o prazo do teste; **24 horas** é o prazo para responder um esclarecimento.
- Bug repetido não é pago: vale só o **primeiro** registro.
- Mac grava com **QuickTime**, Windows com **Screenpresso**, Android com **AZ Recorder**.

## English

**What Crowdtest is:** the crowdtesting platform of **Base2**, a software testing company in Belo Horizonte, Brazil. Everything is in **Portuguese**. Two work models: **Pay-Per-Test** (scripted test cases, paid per approved execution) and **Pay-Per-Bug** (exploratory testing, paid per approved bug).

**Sign-up:** web or Android/iOS apps. Fill in as much profile data as possible, since many projects need a specific profile or device. Missing devices can be requested from support by email.

**Screen recording is mandatory for every test.** Android: enable Developer options and *Show taps*; suggested app AZ Recorder. iOS: built-in recorder. Mac: **QuickTime Player** (File, New Screen Recording). Windows: **Screenpresso**.

**Finding projects:** *public* projects need no form (log in, open "Projetos Disponíveis"; limited seats). *Private* projects target a specific profile (city, age, bank, device), use an application form and send invites by email (check spam). **Most projects are private**, so a complete profile matters.

**Running a test case:** click "Executar próximo teste" (the pay is in the title); read title, description, preconditions, feature, expected result and notes; you may skip or cancel. Record, follow and tick each step. Required fields: **actual result, device, evidence**; optional: extra steps, additional notes. Status: **Passed** (goal reached, even with minor issues), **Failed** (main goal not reached), **Blocked** (an application failure prevented testing). Time limit: usually **2 hours**, after which the test goes to someone else.

**Reporting a bug (exploratory):** first read the list of **allowed features** (bugs outside it are rejected). Click "Nova Ocorrência". Required: specific title, bug type, description, steps, expected result, feature, device and evidence; optional: precondition and extra info. **Only the first reporter is paid**, so search for duplicates first. When the project's bug budget runs out it **pauses automatically**.

**Clarifications:** answer within **24 hours** via the "Esclarecimentos" button, or the item is **automatically rejected**.

**Bug types and pay (may change without notice):** Blocker R$ 20 · Security R$ 20 · Functional R$ 10 · Interface R$ 5 · Improvement R$ 3 · Text R$ 2. Test case: about R$ 20 on average.

**Payment:** on the **10th of each month**, **PayPal only**, approved work only. Add the PayPal email under Profile, Financial data, Edit.

**Welcome project:** unpaid training; an approved test execution and an approved bug are required to unlock public projects.
